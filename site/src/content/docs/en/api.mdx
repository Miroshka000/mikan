The panel has a REST API for bots, billing and monitoring. All the methods with their parameters and answers are in the [reference](/mikan/en/api/reference/) on this site, and the same reference is built into the panel itself. Guides: [create a user](/mikan/en/api/create-user/), [your own bot](/mikan/en/api/own-bot/), [SDK](/mikan/en/api/sdk/), [webhooks](/mikan/en/api/webhooks/), [stability and changes](/mikan/en/api/stability/).

## Where the documentation is

:::note[New in 0.5.2.1]
The methods reference on this site and the guides are new in 0.5.2.1, and so are the SDKs and webhooks.
:::

The methods reference: [all API methods](/mikan/en/api/reference/). Every method has its parameters, request body, answers and examples, and it says which key it needs.

In the panel itself: **Settings → Security → API → Open**. The page has:

- the API address and keys;
- a list of all methods with parameters, responses and curl examples, and a "Try it" button for GET requests;
- "Download OpenAPI": a `mikan-openapi.json` file with your panel's address already filled in. It works with Postman, Insomnia, Swagger UI and client generators.

:::caution
The downloaded file contains your panel's secret path. Do not publish it.
:::

The API address is `https://<panel address>:<port>/<secret path>/api/v1`.

## Keys

On the API page, the **New key** button:

- **Name**.
- **Access**: "Read" or "Full access".
- **Expires**: when I revoke it, 30, 90 or 365 days.
- The administrator password and the 2FA code, if it is on.

The key is shown once, and the panel keeps only its hash. Keys are created and revoked only from the panel, not through the API. When the password changes, you can revoke the administrator's keys with a checkbox, and `mikan reset-password` always revokes them.

| Access | What it allows |
|---|---|
| Read | GET only: users, statistics, settings, metrics. Responses contain no subscription links or secret addresses |
| Full access | create and extend users, change plans and connections. Without sign-in, sessions, keys, the audit log, payments, the bot, certificates, updates and panel addresses: those are available only from the panel |

The key goes in a header:

```http
Authorization: Bearer mk_...
```

Errors come in RFC 9457 format (`application/problem+json`), with the error code in the `detail` field. When fields of the request are refused (422, `detail` is `validation`), each field has its own code in `errors[].message` and the field in `errors[].location`, such as `body.port`; `errors[].value` may hold what the code names (the busy port, the line of a rule).

Refusals that come with the key: 401 `unauthorized` (the key is wrong, revoked or expired; many failures from one address close the entrance for a while: 429 `rate_limited`, the time is in the `Retry-After` header), 403 `read_only_key` (a "Read" key tries to change data) and 403 `session_only` (the method is for the administrator's session only).

## Examples

```bash
BASE="https://vpn.example.com:PORT/SECRET-PATH/api/v1"
KEY="mk_..."
```

List active users:

```bash
curl -H "Authorization: Bearer $KEY" "$BASE/users?state=active&limit=10"
```

Create a user on plan 2:

```bash
curl -X POST "$BASE/users" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"name": "Anna", "tariff_id": 2, "contact": "@anna"}'
```

The response has the user with an `id` and the subscription link `sub_url`. More in [Create a user with a key](/mikan/en/api/create-user/).

Extend by 30 days or by a month (one of the two is required):

```bash
curl -X POST "$BASE/users/42/extend" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"days": 30}'
```

Add 10 GB that is valid until used up:

```bash
curl -X POST "$BASE/users/42/grants" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"bytes": 10737418240, "lifetime": "used"}'
```

## All methods

The list of methods is not kept by hand: the reference is built at every build of the site from the file `web/src/api/openapi.json`, which the panel exports itself with the `mikan openapi` command. The methods are grouped by the panel's sections, and each says which key it takes: any, only "Full access", or only the administrator's session.

[Open the reference](/mikan/en/api/reference/)

## Client balances and promo code statistics

The panel has no screens for these methods: they are for scripts, for example to reconcile balances with your books or to build a report on promo codes. They are the [summary of the promo codes](/mikan/en/api/reference/operations/promocode-stats/), [a Telegram account's balance with its last operations](/mikan/en/api/reference/operations/get-balance/) and [the manual change of a balance](/mikan/en/api/reference/operations/adjust-balance/).

Both GET methods are open to any key, "Read" or "Full access":

```bash
curl -H "Authorization: Bearer $KEY" "$BASE/promocodes/stats"
curl -H "Authorization: Bearer $KEY" "$BASE/balances/123456789"
```

The amounts of a balance and its operations come in hundredths of the currency (the `currency` of the answer): positive is money in, negative is money out. An operation's `kind` is `topup`, `spend`, `refund` or `adjust`.

Changing a balance moves a client's money, so an API key cannot call it: the answer is 403 `session_only`. It is available only from the administrator's session, with a body like `{"delta": -5000, "note": "refund for the downtime"}`. `delta` is in hundredths of the currency, a negative one debits, and the balance never goes below zero (the answer is `balance_low`). `note` is required and shown to the client in the balance history. Every change goes to the audit log.
