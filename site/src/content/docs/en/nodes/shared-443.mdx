:::

Port 443 looks the most ordinary on a server and is the least often blocked. But by default only one protocol can live on it. The shared port 443 is the node's **SNI router**: the node itself listens on 443 and hands connections to the right protocols by the site name the client gives at the start of the TLS handshake (SNI). So REALITY, VLESS and Trojan with TLS and AnyTLS live on 443 at once, and you need no nginx or HAProxy as in [Connecting behind a proxy](/mikan/en/protocols/behind-proxy/).

## Turn it on

<Steps>

1. Free port 443/tcp on the node's server. If a node protocol or another program holds it, the router does not start, and the node card shows "Port 443 cannot be taken" with the reason. Move the protocol off 443 (on a new node that is VLESS · REALITY · XHTTP) to another port, and in step 3 turn "Through shared 443" on for it: clients still come to 443.

2. **Nodes → the node → Configure**, the **Shared port 443 (SNI router)** switch. Save.

3. In the settings of each protocol that should live on 443 turn on **Through shared 443**. If the node's router is off, the panel says so: the protocol stays on its own port until the router is on.

</Steps>

Clients get port 443 with their next subscription update.

Only VLESS, Trojan and AnyTLS over TCP with TLS or REALITY can sit on the shared 443: the router has to read the TLS handshake. Hysteria2, TUIC and other UDP protocols stay on their own ports.

## How the node picks a protocol

The router reads the client's first message and takes the site name from it:

- for **REALITY** these are the names of the protocol's camouflage site (its SNI);
- for protocols **on the node's certificate** (VLESS, Trojan, AnyTLS with TLS) it is the name clients are given: the protocol's SNI or, if it has none, the node's domain;
- an **unknown name** (and non-TLS traffic) goes to the first REALITY protocol in order and on to its camouflage site, as on a real server. A scanner that came with a strange name sees an ordinary site.
- a **protocol behind a CDN** (its settings name a CDN's address, the "Behind a CDN" block) takes unknown names and connections with no name in place of REALITY since 0.5.2.1: a CDN comes to the server asking for a name of its own settings (the origin's host, the zone's apex, no name for an origin given as an address), and the panel cannot know it. A stranger with a name of his own gets what that protocol answers to a request that is not its client's: the node's certificate and the front page.

So each protocol on the shared 443 needs a name of its own. The router cannot tell apart two REALITY protocols with the same camouflage site: give one of them another site.

## The client's real IP

Protocols behind the router listen on loopback (127.0.0.1) only, on their own ports. The router hands them the connection with PROXY protocol: a header carries the client's address. So **devices, limits and filters still see the real IP**, not 127.0.0.1. A protocol's own port does not disappear from the list, but it is closed from outside: only 443 faces out. In the subscription the panel puts port 443 for clients itself.

PROXY protocol is supported by the Citrus core that the nodes run on in the beta, see [Nodes](/mikan/en/nodes/nodes/).

## If it does not work

- The node card shows the router's error if 443 is taken.
- Port 443/tcp is open in the server's firewall and at the hoster.
- A protocol with TLS on the node's certificate has the node's domain with a public certificate.
- The client updated the subscription and got port 443.

## The "Secure" preset

Since 0.5.2.1 everything on this page is turned on in one action: **Settings** → **Security** → **Security presets** → "Secure" → **Show the changes**. The panel lists, node by node, what it would change: which protocols go behind the shared 443, which get a new name (the panel's domain and the subscriptions' domain; strangers' sites next to the server only with the "Find sites next to the server" button), where the SNI router, the API lock and the front page are turned on. Nothing is written until you press **Apply**.

What the preset cannot do it names apart: a protocol with none of your names left, a protocol left on a stranger's site, port 443 held by a protocol that cannot share it, SSH among the "Open ports of the server". Clients connect to the old addresses until they refresh the subscription. "Standard" takes the protocols back to ports of their own the same way.
