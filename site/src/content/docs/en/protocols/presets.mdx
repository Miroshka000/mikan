The **Protocols** section holds the protocols clients use to reach your nodes. Add a new one from a preset with the **Add** button: keys, passwords and certificates are created for you, and all you pick is the node and, if you like, the port.

| Own config | | a mihomo listener template in YAML |

:::caution[One-key protocols]
Sudoku, Snell and Shadowsocks-2022 with the ChaCha20 method work with a single key for everyone. The node cannot tell users apart, so these protocols have no traffic accounting, limits, device binding or automatic fixes. A disabled or expired user keeps access until the key changes, and the only way to change it is to delete the connection and add it again.

Shadowsocks-2022 with the AES methods (`2022-blake3-aes-128-gcm` by default) gives every client a key of its own, and all of this works on it as on VLESS.
:::

:::note[TLS in TLS]
In Trojan and in VLESS without Vision (REALITY XHTTP, gRPC and PQ, TLS XHTTP, TLS WebSocket and both CDN ones) the TLS of the sites a client opens goes inside the protocol's own TLS. DPI can tell a proxy by the sizes of the first packets. Vision and AnyTLS hide this pattern: keep a protocol with one of them next to it. The list of presets marks such protocols "TLS in TLS".
:::

## Who gets what

The subscription detects the app and sends it only what it can run. The connection form shows this on the "Delivered to" line.

| VLESS · TLS · WebSocket | yes | yes | yes |

A Clash app gets the newer protocols only if it reports a recent enough core version: for example, Gecko needs mihomo 1.19.26+ and ShadowQUIC 1.19.29+. If the app doesn't report a version, these protocols are not sent to it.

## Connection settings

The **Configure** button opens the tabs "Main", "Masking" (XHTTP only) and "Config (YAML)".

- **Name in the subscription**: how the connection is named in apps.
- **Port**. For Hysteria2 you can set a range, for example `20000-30000`: clients hop between ports, so blocking a single port is pointless. Open the whole range for UDP in the firewall.
- **Camouflage site (REALITY)**: `www.microsoft.com:443` by default. The buttons are "Check" and "Find near the server" (looks for sites in the same /24 network as the node). If the panel has a domain, you can pick your own domain. If an IP is given instead of a name, the "Site domain (SNI)" field is required.
- **Obfuscation** for Hysteria2: Salamander or Gecko. Gecko cuts the QUIC handshake into pieces of random size with padding, against DPI that recognizes QUIC by packet sizes. Only Clash apps on mihomo 1.19.26+ receive it, so keep a plain Hysteria2 next to it.
- **TLS fingerprint**: as in the settings (Chrome by default), Chrome, Firefox, Safari, iOS, Android, Edge, 360, QQ, a random browser, or "Own…" with any uTLS profile name, for example `chrome120`. The shared default is set in **Settings → Subscription**. Hysteria2 and TUIC have no fingerprint.
- **Way out to the internet**: direct, [WARP](/mikan/en/nodes/warp/) or [via a node](/mikan/en/nodes/cascades/).
- **Server group**: the group decides which traffic the protocol spends: the main one, a limit of its own, none, or it is not included in the plan. A protocol in no group spends the main traffic. See [Server groups and traffic packages](/mikan/en/billing/pools/).
- **In auto select** (since 0.5.2.1): turn it off if the apps must not pick this protocol on their own. It leaves the subscription's "Auto" and stays in the list and in its country's group. A whole node has the same switch, see [In auto select](/mikan/en/nodes/nodes/#in-auto-select).
- **Behind a proxy (nginx, HAProxy)**: see [Behind a proxy](/mikan/en/protocols/behind-proxy/).
- **Behind a CDN** (since 0.5.2.0): the CDN's address for clients and the client's real IP from a header, only for VLESS and Trojan on the node's certificate over XHTTP, WebSocket and gRPC, see [Behind a CDN](/mikan/en/protocols/cdn/).
- **Through shared 443** (since 0.5.2.0): the protocol shares the node's port 443 with others by TLS name, see [Shared port 443](/mikan/en/nodes/shared-443/).
- **Automatic fixes**: switches for moving the port and changing the site, see [Automatic fixes](/mikan/en/protocols/autotune/).

## Copying a protocol

:::note[New in 0.5.2.0]
Copying is new in 0.5.2.0.
:::

The **Copy** button in a protocol's row makes one more like it: the same settings with keys of its own, and clients get the copy as one more connection. In the window pick:

- **To which node**: the same one or another. A copy on the same node listens on another port.
- **Port**: empty means the same port, or the first free one if it is taken.
- **Camouflage site**, for REALITY: keep it or pick another.

The address for clients, the CDN and the path are copied as they are. If the other node has its own, fix them in the copy's settings.

## Exit for several protocols at once

:::note[New in 0.5.2.0]
The group exit is new in 0.5.2.0.
:::

Tick several protocols in the list (or "Choose all") and a **Way out to the internet** button appears above the list. It sets the exit for everything ticked at once:

- **Direct**: sites see the server's IP;
- **Through its node's WARP**: the node must have [WARP](/mikan/en/nodes/warp/) set up;
- **Via a node**: pick another node, see [Cascades](/mikan/en/nodes/cascades/).

It is the same "Way out to the internet" field from a protocol's settings, only for many protocols at once.

## Own config

The "Own config" preset opens a YAML editor with a mihomo listener of type vless, trojan, hysteria2, tuic or anytls. mikan fills in the name, port, address, users and certificate itself. The "Check" button validates the config before saving.

:::note[VMess is gone]
Since 0.5.2.0 the nodes run the Citrus core, and it has no VMess. VMess connections from before become VLESS on the same transport with the same users when you update. Clients get the new keys with their next subscription update.
:::

## From the command line

```bash
mikan inbound list
mikan inbound add                        # shows the list of presets
mikan inbound add hysteria2 --port 20000-20100 --node 2
mikan inbound set vless-xhttp --port 2443
```

On the panel server the new port is opened in ufw automatically, and the node picks up the changes within 30 seconds.

## Camouflage sites from the command line

```bash
mikan targets scan                       # find suitable sites near the server
mikan targets check --dest www.example.com:443
mikan targets apply --dest www.example.com:443 --all
```
