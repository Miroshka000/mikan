---
title: The mikan command
description: Reference for the mikan server management command.
---

Running `mikan` with no arguments opens a menu in the terminal: status, updates, logs, access, REALITY sites, nodes, backups. The same actions are available as commands. Run them as root.

## Server

| Command | What it does |
|---|---|
| `mikan status` | containers, CPU and memory, panel state, available update |
| `mikan doctor [--json]` | check the panel's or node's server, a hint on every line, see below. `--json` prints the report as JSON, secrets cut out |
| `mikan support <code> [--dry-run]` | send support the check, the status and the last log lines (secrets cut out) with the code from your ticket, see below |
| `mikan logs [panel\|node]` | live logs, <kbd>Ctrl</kbd>+<kbd>C</kbd> stops |
| `mikan restart` | restart the containers |
| `mikan api-lockdown [status\|off]` | on a node's server: the state of the firewall rule "Node API from the panel's IP only", or lift it at once, see [Hardening a node](/mikan/en/nodes/hardening/) |
| `mikan support-access on\|off` | allow or forbid [support access](/mikan/en/operations/support-access/) on this server; `off` holds whatever the panel says |
| `mikan update [--check]` | update now, a backup first, rollback on failure. `--check` only checks |
| `mikan install [flags]` | install; on an installed server it opens the menu |
| `mikan uninstall [-y]` | stop and remove the command, data stays in `/opt/mikan` |

`mikan doctor` works on a panel's server and on a node's server. It checks Docker and the containers, that the ports are listening, ufw rules for the node API port, the panel port and the protocol ports, time sync (`timedatectl` and the HTTP Date header from github.com, 30 s tolerance), DNS, outbound HTTPS to github.com and ghcr.io (needed for updates), disk (✗ under 500 MiB, ! under 2 GiB) and memory. On a node it also re-sends the hello to the panel and prints the result. Each line is marked ✓, ! or ✗ and has a fix line; if anything is ✗, the command exits with a non-zero code. `mikan status` suggests `mikan doctor` when something is wrong. This is the tool for when the panel cannot reach the node at all. The same set of checks for the panel's server is in the panel itself: the "Check server" button in **Settings → System**.

The panel runs `mikan doctor` and `mikan restart` on its own server, and on a node's server over the node API, without SSH: it writes a request file into its data directory and a systemd unit (`mikan-doctor-request.path`, `mikan-restart-request.path`, installed by the installer and by `mikan update`) runs the command and returns the report. A server installed before 0.5.2.0 needs one `mikan update` for that. The logs of the panel and of the nodes are shown in the panel as well, with tokens, keys, passwords and subscription links cut out. All of it is on the [Diagnostics](/mikan/en/operations/diagnostics/) page.

`mikan support <code>` is for the case when the panel is down or the node is out of the panel's reach. Take the code from your support ticket, run the command as root: it collects the same report as `mikan doctor --json`, `mikan status` and the last 300 lines of the containers' logs, cuts the secrets out and sends one JSON document to the support desk (`MIKAN_SUPPORT_URL` points it elsewhere). The settings files (`config.json`, `secrets/`, and `.env` on older servers), keys and certificates are not read and not sent. `--dry-run` prints what would be sent and sends nothing.

## Settings files

:::note[Secrets out of .env: 0.5.2.0]
All of the server's settings used to be in `/opt/mikan/.env`. Since 0.5.2.0 they are split, and nothing secret is in a container's environment any more: `docker inspect` and `/proc/<pid>/environ` show only the paths of files.
:::

| Path | What is there | Permissions |
|---|---|---|
| `/opt/mikan/config.json` | the plain settings: the image, the version, the mode, `MIKAN_ACME_LISTEN`, `MIKAN_AUTO_UPDATE` and others. A JSON object of strings | root only |
| `/opt/mikan/secrets/` | the secrets, each a file of its own: `postgres_password` and `database_url` (the database's password and address on a panel's server), `node_join` (the join key on a node's server) | the folder 0700, each file 0400 and readable only by the container that needs it |

Docker Compose mounts the files of `secrets/` into the containers as secrets (`/run/secrets/<name>`). The panel and the node read the password, the database address and the node key from there. A backup holds both `config.json` and `secrets/`, and old archives with `.env` restore as before.

**The next `mikan update` moves an existing `.env` by itself**: it creates the new files first and removes `.env` once mikan already runs on them. A copy stays in the update's backup. A rollback to an older mikan version puts `.env` back. You do not need to do anything by hand.

To change a plain setting by hand, edit `config.json` and run `mikan restart`. For example, to let nginx or Caddy on port 80 pass certificate checks to mikan, add a line to `config.json`:

```json
{
  "MIKAN_ACME_LISTEN": "127.0.0.1:18080"
}
```

(together with the file's other lines, separated by commas). The values go into `compose.yaml` as they are, so they cannot hold `$`, quotes, spaces or `#`. Secrets are changed only through the panel and mikan's commands: `mikan join KEY` on a node changes `node_join`. The `mikan cert proxy <domain>` command sets `MIKAN_ACME_LISTEN` and restarts the node itself.

## Access

| Command | What it does |
|---|---|
| `mikan url` | the panel link and login |
| `mikan reset-password` | a new administrator password; all sessions, API keys and passkeys are revoked |
| `mikan reset-path` | a new secret link, the old one stops working |
| `mikan disable-2fa` | turn off 2FA if the phone is lost |

## Backups

| Command | What it does |
|---|---|
| `mikan backup` | a backup into `/opt/mikan/backups` |
| `mikan restore FILE [-y] [--no-db-snapshot]` | restore from a backup, see [Backups](/mikan/en/operations/backups/) |

## Nodes and connections

| Command | What it does |
|---|---|
| `mikan node list` | the panel's nodes |
| `mikan node add --name NAME --host IP [--domain D] [--api-port P]` | add a node and get a key |
| `mikan node key NODE` | a new node key, the old one stops working |
| `mikan node set NODE [--name] [--host] [--domain] [--enabled=true\|false]` | change a node |
| `mikan join [KEY] [--panel-ip IP]` | on a node: accept a new key from the panel |
| `mikan inbound list` | connections |
| `mikan inbound add PRESET [--port PORT] [--node N]` | add a connection; without a preset it shows the list |
| `mikan inbound set NAME --port PORT [--node N]` | change the port, keys and masking stay |

The panel's own node has number 1, and its address and domain are changed in the panel settings.

## Certificates

| Command | What it does |
|---|---|
| `mikan cert set --cert fullchain.pem --key privkey.pem [--node N]` | your own certificate for the panel or a node |
| `mikan cert show [--node N]` | what is installed now |
| `mikan cert clear [--node N]` | go back to the automatic certificate (for a node: self-signed) |
| `mikan cert proxy <domain>` | nginx or Caddy holds port 80: pass the certificate authority's checks through it to the panel or node (the rule is backed up, the config tested and reloaded) |

## REALITY masking sites

| Command | What it does |
|---|---|
| `mikan targets scan [--node N] [--json]` | find suitable sites near the server |
| `mikan targets check --dest HOST:PORT [--sni NAME]` | check a site |
| `mikan targets apply --dest HOST:PORT [--sni NAME] (--all \| --inbound NAME) [--force]` | set the site for all connections or for one |

For an IP address in `--dest`, `--sni` is required. The site is checked before it is applied, and `--force` skips the check.

## Payment adapters

| Command | What it does |
|---|---|
| `mikan addon list` | what is running and what is in the catalog |
| `mikan addon install ID` | install or update an adapter |
| `mikan addon remove ID` | stop and remove, settings and payments in the panel stay |
