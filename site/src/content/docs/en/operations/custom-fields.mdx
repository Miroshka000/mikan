---
title: Custom fields
description: The admin's own fields on clients and nodes (an order number, a phone, the hoster's account), on the card, in the search and in the API.
---

Since 0.5.2.1. Custom fields are notes the admin keeps on a client or a node, each with a name and a type: an order number, a phone, a link to the server in the hoster's account, a payment date from a contract. They do not affect access: no term, traffic or subscription depends on them. Clients do not see them.

## Adding a field

In **Settings → General → Custom fields**, fill in:

- **Whose field**: clients or nodes.
- **Type**:
  - text;
  - number;
  - yes/no;
  - date;
  - link (`http` and `https` only).
- **Name**: what the card labels the field with.
- **API key**: lowercase Latin letters, digits and `_`, starting with a letter, up to 32 characters. The panel suggests one from the name.

The type and the key cannot be changed later; the name can be changed at any time.

In the list of fields:
- the arrows change the order the cards show the fields in;
- each field shows on how many clients or nodes it is filled in;
- deleting a field deletes its values with it.

Clients and nodes can have up to 30 fields each. A key is unique among the clients' fields and, separately, among the nodes' fields.

## Filling them in

- **On a client:** in the **Custom fields** section of the card, under the note. Save the changes with **Save**.
- **On a node:** in the **Custom fields** block of **Edit node**. The values are saved with the rest of the form.

To clear a field, leave it empty; for a yes/no field, turn the switch off.

If a value does not fit the type, for example "soon" in a date field, the panel saves nothing and says under the field what is wrong.

The search above the clients' list also looks through their field values, for example an order number.

A support operator who may not see the subscribers does not see the clients' fields. They do see the nodes' fields.

## In the API

These endpoints work with the fields themselves:
- `GET /api/v1/custom-fields` lists the fields.
- `POST /api/v1/custom-fields` adds one (`scope`, `key`, `label`, `kind`).
- `PATCH /api/v1/custom-fields/{id}` renames one.
- `PUT /api/v1/custom-fields/order` sets the order.
- `DELETE /api/v1/custom-fields/{id}` deletes one with its values.

A client and a node carry their values in `custom_fields`, an object of key to value. A field with no value is not in it.

`POST /api/v1/users`, `PATCH /api/v1/users/{id}` and `PATCH /api/v1/nodes/{id}` take `custom_fields`. They change only the fields you name, and an empty string clears a value. Values are stored in a normalized form:
- a number as a plain decimal, digit for digit, without extra zeros: `007.50` becomes `7.5`;
- a date as `YYYY-MM-DD`;
- yes as `true`; `false` clears the value.

```json
PATCH /api/v1/users/42
{"custom_fields": {"order_no": "A-1042", "paid_until": "2026-12-01"}}
```
