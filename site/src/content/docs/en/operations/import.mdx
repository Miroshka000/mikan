**Settings → Import** moves users from Marzban, PasarGuard, Remnawave or 3x-ui. You do not need access to the old panel's database: everything goes through its API, and the old panel itself is not changed.

## Move users

<Steps>

1. Pick the panel and enter the **Address of the old panel**, for example `https://panel.example.com`, without the admin path. For 3x-ui the address goes with the port and the panel's secret path, as you open it in the browser: `https://panel.example.com:2053/path`.

2. Access:
   - **Marzban**: the administrator's username and password;
   - **PasarGuard**: a username and password, or an API key with the `users:read` permission;
   - **Remnawave**: an API token with permission to read users;
   - **3x-ui**: the administrator's username and password, or an API token (Settings → API tokens, in newer versions). If the administrator signs in with a two-factor code, a token is needed.

3. Pick a **Plan**: users get its protocols, traffic reset rule and server groups.

4. "Check" shows how many users were found, how many are new and how many are already here.

5. "Import" starts the import in the background, so you can close the page.

</Steps>

The traffic limit, used traffic, term, device limit and note are carried over. Users whose names already exist in mikan are skipped. The old reset rule, groups and connections are not carried over. Users "on hold" start their term at the moment of import.

### 3x-ui

In 3x-ui clients live inside the inbounds, so the import gathers them into users this way:

- clients with the same `subId`, on any inbounds, are one user, one subscription. The user is named after the `email` of the first of them (in the order of the inbounds), the note is their comments, the contact their Telegram ID;
- 3x-ui has limits per client, and the user gets their sum: the traffic limit is the sum of the limits, used traffic the sum of what they used; if one of the clients has no limit, the user has none. The term is the latest one, and a client without a term makes the user's term endless;
- the device limit is `limitHwid` of 3x-ui 3.x, and in the versions without it the limit of addresses at once (`limitIp`), the largest of the clients';
- a term "from the first use" (a negative `expiryTime`) starts at the import, as "on hold" does from the other panels;
- a client without a `subId` comes over as a user of its own, without an old link;
- a client that is only on inbounds of protocols mikan has not (VMess, WireGuard, MTProto and others) does not come over: "Check" lists it among those mikan will not take, with the reason. mikan's protocols are VLESS, Trojan, Shadowsocks, Hysteria2 and TUIC.

A disabled client comes over disabled. The limits and terms of the inbounds themselves are not carried over.

:::caution
Links that were revoked in the old panel work again after the import. If that matters, reissue them.
:::

## Old subscription links

For clients to change nothing, point the old domain at the mikan server and set up the **Old subscription links** card:

- **Path of the old links**: `sub` for Marzban and PasarGuard, `api/sub` for Remnawave. For 3x-ui it is the "Subscription path" of its Settings → Subscription (`sub` by default): the old link is the client's `subId`, which comes over as it is. Empty: off.
- Marzban and PasarGuard also need the **Signing secret of the old panel**. It is stored in the old panel's database:

  ```sql
  SELECT secret_key FROM jwt;
  ```

  Without it, the old links will not open.
- Set the subscription port in **Settings → Subscription** if the old panel served subscriptions on a different port.

The bot accepts old links, and the user card shows the old link (Remnawave, 3x-ui) or that it works. Reissuing a link disables the old one too.
