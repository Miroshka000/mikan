---
title: Подключение за прокси
description: Протоколы за nginx stream или HAProxy на одном порту 443, адрес и порт для клиентов.
---

Если порт 443 на сервере уже держит nginx или HAProxy, протоколы можно спрятать за ним: прокси принимает соединения на 443 и по SNI раздаёт их протоколам на `127.0.0.1:444`, `:445` и так далее.

## Настроить

В настройках подключения блок **За прокси (nginx, HAProxy)**:

- **Где нода слушает**: «Все адреса» (как обычно), «Только localhost» (127.0.0.1) или «Свой IP».
- **Адрес для клиентов**: какой адрес получат клиенты в подписке. Пусто: адрес ноды.
- **Порт для клиентов**: обычно 443, порт прокси. Пусто: порт подключения.
- **SNI для клиентов**: для протоколов со своим TLS-именем. У REALITY им остаётся домен сайта маскировки, по нему прокси и различает соединения.

:::caution
Если нода слушает только localhost, а порт для клиентов не задан, клиенты пойдут на закрытый снаружи порт. Панель предупредит об этом: укажите порт прокси.
:::

## Несколько адресов для клиентов

С 0.5.2.1 у подключения есть блок **Адреса для клиентов**: места, через которые клиенты до него доходят, у каждого свои адрес, порт, SNI, HTTP Host и отпечаток. Первый, **По умолчанию**, — это адрес, порт и SNI выше вместе с отпечатком: его клиенты и получают, и меняется он вместе с ними. Другие адреса сохраняются в том порядке, в каком вы их добавили, но в подписку пока не попадают: в следующей версии из каждого выйдет своя запись сервера. Адрес по умолчанию удаляется только вместе с подключением.

В API то же самое: `GET`, `POST /api/v1/inbounds/{id}/hosts` и `PUT`, `DELETE /api/v1/inbounds/{id}/hosts/{host_id}`. Как и адрес для клиентов, адреса меняются только в сессии админа, не ключом API.

## Пример для nginx stream

```nginx
stream {
    map $ssl_preread_server_name $mikan {
        www.microsoft.com  127.0.0.1:444;   # VLESS · REALITY, сайт маскировки
        default            127.0.0.1:4430;  # ваш сайт
    }
    server {
        listen 443;
        ssl_preread on;
        proxy_pass $mikan;
    }
}
```

Это набросок: имена и порты подставьте свои.

## Что меняется

У подключения за прокси автоподбор выключен и не включается:

- порт не переносится, иначе прокси не узнает новый;
- сайт маскировки не меняется, ведь прокси может маршрутизировать по его имени.

## Через CDN

С версии 0.5.2.0 для CDN есть свои пресеты и блок **За CDN** с настоящим IP клиентов, см. [За CDN](/mikan/protocols/cdn/). Ниже способ без них, на WebSocket.

**VLESS · TLS · WebSocket** проходит через CDN (Cloudflare, Яндекс Cloud CDN): клиенты идут на адрес CDN, а CDN передаёт соединение ноде. Там, где IP сервера заблокирован, а сеть CDN нет, это может спасти.

1. Добавьте подключение **VLESS · TLS · WebSocket**. Порт оставьте 2053: Cloudflare пропускает к серверу только порты 443, 2053, 2083, 2087, 2096 и 8443.
2. В CDN заведите домен, например `cdn.example.com`, с адресом сервера ноды и включите проксирование (в Cloudflare оранжевое облако). Режим SSL в Cloudflare: Full.
3. В блоке **За прокси** подключения: адрес для клиентов `cdn.example.com`, порт 443, SNI `cdn.example.com`.

Остальные протоколы ноды CDN не касается: они идут на её адрес как раньше.
