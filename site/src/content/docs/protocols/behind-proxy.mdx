title: Подключение за прокси
description: Протоколы за nginx stream или HAProxy на одном порту 443, адрес и порт для клиентов.
---

Если порт 443 на сервере уже держит nginx или HAProxy, протоколы можно спрятать за ним: прокси принимает соединения на 443 и по SNI раздаёт их протоколам на `127.0.0.1:444`, `:445` и так далее.

## Настроить

В настройках подключения блок **За прокси (nginx, HAProxy)**:

- **Где нода слушает**: «Все адреса» (как обычно), «Только localhost» (127.0.0.1) или «Свой IP».
- **Адрес для клиентов**: какой адрес получат клиенты в подписке. Пусто: адрес ноды.
- **Порт для клиентов**: обычно 443, порт прокси. Пусто: порт подключения.
- **SNI для клиентов**: для протоколов со своим TLS-именем. У REALITY им остаётся домен сайта маскировки, по нему прокси и различает соединения.

:::caution
Если нода слушает только localhost, а порт для клиентов не задан, клиенты пойдут на закрытый снаружи порт. Панель предупредит об этом: укажите порт прокси.
:::

## Несколько адресов для клиентов

С 0.5.2.1 у подключения есть блок **Адреса для клиентов**: места, через которые клиенты до него доходят, у каждого свои адрес, порт, SNI, HTTP Host и отпечаток. Первый, **По умолчанию**, — это адрес, порт и SNI выше вместе с отпечатком: его клиенты и получают, и меняется он вместе с ними. Каждый следующий адрес — ещё одна запись сервера в подписке, сразу за адресом по умолчанию и в том порядке, в каком вы их добавили. Её имя — имя подключения с номером («Fast 2»). Пустое поле такого адреса — то, что клиенты получают без него: адрес и TLS-имя ноды (у REALITY — первое имя из его списка сайтов), порт подключения, отпечаток панели, а не поле адреса по умолчанию. Заданный порт у Hysteria2 отменяет диапазон портов: клиент ходит только на него. Адрес по умолчанию удаляется только вместе с подключением.

У каждого адреса, и у адреса по умолчанию тоже, есть и поля только его: ALPN (h3, h2, http/1.1; только с TLS на сертификате ноды и у QUIC-протоколов), версия IP, мультиплексирование (sing-mux: у VLESS, Trojan и Shadowsocks, не по XHTTP и не с Vision) и «Через CDN со своим сертификатом» (у VLESS и Trojan, которые можно поставить за CDN). Clash-приложения и sing-box получают все; Xray-приложения (Happ, INCY, v2RayTun и другие) — ALPN и версию IP, без мультиплексирования: в Xray его нет. С «Через CDN» самоподписанный сертификат ноды для этого адреса не пинится: CDN показывает свой.

Поле **Дробить TLS-рукопожатие** режет ClientHello, который отправляет приложение, чтобы DPI не прочитал в нём имя сервера: так проходит домен, который блокируют по SNI, в том числе домен CDN. Есть два способа:

- **на TLS-записи** — ClientHello уходит несколькими TLS-записями в одном пакете. Почти не замедляет подключение и обходит DPI, который читает только первую запись;
- **на TCP-пакеты с паузой** — каждая запись уходит отдельным пакетом. Подключение начинается на несколько RTT дольше, зато это обходит и DPI, который смотрит только первый пакет.

Поле есть у VLESS, Trojan и AnyTLS с TLS на сертификате ноды или за CDN. У REALITY его нет: в ClientHello там имя чужого сайта маскировки, которое DPI и так пропускает. Получают его приложения на sing-box (SFA, SFI, SFM, SFT) и на Xray, когда им уходят конфиги Xray (Happ и INCY), а также свои шаблоны Xray. Clash-приложения и ссылки его не получают: в mihomo такой настройки нет, а у ссылок нет общего для приложений параметра.

У адреса может быть и своё **имя в подписке**, до 48 символов, с переменными заголовка подписки: `{brand}`, `{name}`, `{tariff}`, `{date}`, `{days}`, `{used}`, `{left}`, `{total}`, `{devices}`. Они заполняются для каждого клиента при обновлении подписки: «`🇳🇱 NL · осталось {left}`» у одного клиента станет «🇳🇱 NL · осталось 12.5 ГБ». Пустое имя — имя подключения (у следующих адресов с номером); его же клиент получит, если после подстановки имя вышло пустым или совпало со встроенной политикой mihomo (DIRECT, REJECT…). Запятые и кавычки из значений заменяются пробелами. Имя меняется вместе со значениями, а некоторые приложения помнят выбранный сервер по имени и после такого обновления его сбрасывают.

В полях **Ещё адреса** и **Ещё SNI** (по одному в строке, до 16) можно дать адресу несколько вариантов. Каждый клиент получает один из адреса и этого списка, SNI — так же и отдельно от адреса. Выбор зависит от токена подписки: у клиента он одинаковый при каждом обновлении, а разные клиенты распределяются по вариантам примерно поровну. Так можно разнести клиентов по нескольким доменам одного CDN или по нескольким серверам впереди ноды. «Ещё SNI» есть там же, где и SNI: у протоколов на сертификате ноды, не у REALITY. В превью подписки показывается сам адрес, без выбора.

Поля **Кому выдавать по статусу** и **Пробные** решают, кому адрес попадает в подписку. Статусы — активна (истекающая тоже), лимит исчерпан, истекла, отключена; ни одного или все — всем. Пробные: всем, только пробным или всем, кроме пробных; пробный — пришёл с пробного периода и ничего не оплатил сверх него (продление админом пробный не отменяет). Так можно дать пробным отдельный сервер или истёкшим — адрес со страницей продления. Неактивные подписки получают серверы, только если в настройках подписки выключена заглушка вместо серверов. Скрыть можно и адрес по умолчанию: тогда клиент получает только остальные, а подключение, у которого скрыты все адреса, ему не выдаётся. В превью подписки видны все адреса.

Поле **Группы** выдаёт адрес по [группе клиента](/mikan/billing/groups/): всем, только выбранным группам или всем, кроме выбранных. Группа клиента — своя из карточки или группа его тарифа; клиент без группы не входит ни в одну. Так можно дать адрес через CDN только мобильным клиентам или спрятать служебный адрес от пробной группы. Если все группы адреса «только выбранным» удалены, адрес не выдаётся никому, пока ему не выберут другие: панель пишет об этом под полем.

В API то же самое: `GET`, `POST /api/v1/inbounds/{id}/hosts` и `PUT`, `DELETE /api/v1/inbounds/{id}/hosts/{host_id}`. Как и адрес для клиентов, адреса меняются только в сессии админа, не ключом API.

## Пример для nginx stream

```nginx
stream {
    map $ssl_preread_server_name $mikan {
        www.microsoft.com  127.0.0.1:444;   # VLESS · REALITY, сайт маскировки
        default            127.0.0.1:4430;  # ваш сайт
    }
    server {
        listen 443;
        ssl_preread on;
        proxy_pass $mikan;
    }
}
```

Это набросок: имена и порты подставьте свои.

## Что меняется

У подключения за прокси автоподбор выключен и не включается:

- порт не переносится, иначе прокси не узнает новый;
- сайт маскировки не меняется, ведь прокси может маршрутизировать по его имени.

## Через CDN

С версии 0.5.2.0 для CDN есть свои пресеты и блок **За CDN** с настоящим IP клиентов, см. [За CDN](/mikan/protocols/cdn/). Ниже способ без них, на WebSocket.

**VLESS · TLS · WebSocket** проходит через CDN (Cloudflare, Яндекс Cloud CDN): клиенты идут на адрес CDN, а CDN передаёт соединение ноде. Там, где IP сервера заблокирован, а сеть CDN нет, это может спасти.

1. Добавьте подключение **VLESS · TLS · WebSocket**. Порт оставьте 2053: Cloudflare пропускает к серверу только порты 443, 2053, 2083, 2087, 2096 и 8443.
2. В CDN заведите домен, например `cdn.example.com`, с адресом сервера ноды и включите проксирование (в Cloudflare оранжевое облако). Режим SSL в Cloudflare: Full.
3. В блоке **За прокси** подключения: адрес для клиентов `cdn.example.com`, порт 443, SNI `cdn.example.com`.

Остальные протоколы ноды CDN не касается: они идут на её адрес как раньше.
