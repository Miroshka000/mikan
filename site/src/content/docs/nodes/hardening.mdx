Две настройки в **Ноды → нода → Настроить** делают сервер ноды менее заметным для сканеров. У ноды на сервере панели («Своя нода») их нет: она общается с панелью через сокет и порта API не открывает. Третья, [открытые порты сервера](#открытые-порты-сервера), есть у всех нод: она решает, до чего на самом сервере доходят клиенты ноды.

## API ноды только с IP панели

Переключатель **API ноды только с IP панели**. Порт API ноды нужен только панели, но сканеры находят любые открытые порты. Сертификат с пином и ключ не пустят их внутрь, а всё же до рукопожатия TLS они доходят. С этой настройкой нода отвечает на порт API только адресам панели.

Как это работает, в два слоя:

1. Сама нода отказывает чужим адресам в соединении.
2. Нода просит свой сервер поставить правило файрвола `nftables` (таблица `inet mikan_api`), которое отбрасывает TCP на порт API от всех адресов, кроме панели и loopback. Сканер не доходит до ноды вообще. Остальной файрвол правило не трогает, а правила ufw продолжают действовать на то, что оно пропустило. Правило ставит системный сервис `mikan-apilock` на сервере ноды.

Адрес панели и адрес, с которого панель подключилась к ноде, нода берёт сама. Если панель ходит к нодам не со своего публичного IP (NAT, второй адрес), добавьте адреса в поле **Ещё адреса панели**: адреса или сети через запятую, до 16.

:::tip[Если панель переехала на другой IP]
Нода не потеряется. Если панель не появлялась на ноде 15 минут, правило снимается само, панель подключается с нового адреса, и правило возвращается уже с ним.
:::

### Если правило мешает: mikan api-lockdown

На сервере ноды от root:

```bash
mikan api-lockdown status   # состояние правила (команда без аргумента делает то же)
mikan api-lockdown off      # снять правило сразу
```

`off` убирает правило и открывает порт, нода перестаёт отказывать в течение десяти секунд. Правило вернётся, когда панель в следующий раз подключится к ноде с включённой настройкой. Чтобы оно не возвращалось, выключите переключатель в настройках ноды в панели. Команда работает только на сервере ноды: на сервере панели она остановится с ошибкой.

`mikan doctor` на ноде тоже показывает состояние правила и подсказывает команду.

### Нет nftables

Без пакета `nftables` нода всё равно закрывает порт сама (первый слой), но сканеры доходят до неё. В карточке ноды будет сообщение «Нода закрывает порт сама, но правило файрвола на её сервере не поставлено» и причина. Поставьте пакет на сервере ноды:

```bash
apt install nftables
```

Правило появится само в течение минуты.

Сервер ноды, поставленный до 0.5.2.0, получает системный сервис для правила после `mikan update` на нём, см. [Ноды](/mikan/nodes/nodes/#обновление-нод-из-панели).

## HTTP → HTTPS на порту 80

Переключатель **HTTP → HTTPS**. Нода занимает порт 80 и отвечает на обычный HTTP редиректом 301 на https, как настоящий сайт. Закрытый порт 80 выдаёт голый VPN-сервер, а редирект делает его похожим на обычный сайт.

Сертификаты по HTTP-01 продолжают выпускаться: проверки центра сертификации на `/.well-known/acme-challenge/` нода обрабатывает как прежде, см. [Сертификат ноды](/mikan/nodes/nodes/#сертификат-ноды).

Не включайте это, если порт 80 нужен другому веб-серверу на этом сервере. Если порт занят, карточка ноды покажет «Порт 80 не занять» и причину.

## Открытые порты сервера

:::note[С версии 0.5.2.1]
Есть у всех нод, в том числе у своей ноды панели.
:::

Поле **Открытые порты сервера**. Подключение с ноды на адрес её же сервера идёт через интерфейс `lo`, который файрвол обычно пропускает целиком. Поэтому клиент, подключённый к ноде, мог бы дойти до всего, что слушает публичный адрес сервера, даже если снаружи порт закрыт: до базы данных, мониторинга или SSH с доступом только со своего IP.

Ядро ноды таких подключений не пропускает. На адресе самого сервера клиентам открыты только:

- порты 80 и 443: сайт или reverse proxy на сервере и так доступен всем, а без них он открывался бы отовсюду, кроме этой ноды;
- на своей ноде панели ещё порт панели и порт подписок: иначе клиент, идущий через неё, не открыл бы панель и не обновил подписку.

Панель на другом сервере это не затрагивает: для ноды это чужой адрес.

Если клиентам нужна служба на сервере ноды, например свой DNS, укажите её порт в этом поле: через запятую, до 16 портов. Порт открывается и для TCP, и для UDP. Файрвол такие подключения не закрывает, поэтому SSH и базы данных сюда не добавляйте.

Ядро узнаёт адреса сервера по его сетевым интерфейсам. На сервере за NAT публичного адреса на интерфейсе нет, и такие подключения эта защита не закрывает: они уходят в сеть хостера и возвращаются снаружи, как обычные.

Нода версии до 0.5.2.1 и нода под панелью версии до 0.5.2.1 эту защиту не включают.

## Как сервер выглядит снаружи

:::note[С версии 0.5.2.1]
Строка «Как сервер выглядит снаружи» есть в проверке любой ноды.
:::

**Ноды → Проверить ноду** в конце показывает, что в настройках ноды выделяет её сервер для того, кто смотрит на него со стороны: для сканера, который подключается к портам, и для сети, которая видит, куда ходят клиенты. Это предупреждения, не ошибки: всё работает, но сервер проще отличить от обычного сайта.

| Предупреждение | Что сделать |
|---|---|
| Несколько сайтов маскировки на ноде | Оставьте один сайт на все протоколы REALITY: обычный сервер не держит сертификаты нескольких чужих сайтов |
| Сайт маскировки: почтовое имя или динамический DNS | Возьмите обычный сайт: «Подобрать рядом с сервером» показывает такие первыми |
| Протокол на стандартном `www.microsoft.com` | Подберите сайт рядом с сервером: сертификат Microsoft на адресе хостинга заметен |
| TLS-протоколы на трёх и больше отдельных портах | Включите [общий порт 443](/mikan/nodes/shared-443/): снаружи останется один порт, как у сайта |
| Сервер за CDN принимает и прямые подключения | Держите протоколы за CDN на отдельной ноде: прямые подключения выдают адрес, который CDN прячет |
| Порт API ноды открыт всем | Включите «API ноды только с IP панели», см. выше |
| В домене есть «vpn», «proxy» или название протокола | Возьмите нейтральное имя: оно видно в каждом подключении и стоит в сертификате |

Проверка читает только настройки панели, к ноде она для этого не подключается, поэтому строка есть и у ноды, которая не отвечает.

Чего панель проверить не может, но стоит держать в уме: CDN знает адрес сервера, который прячет, из собственных настроек; одна подписка, в том числе пробная, называет адреса всех серверов, которые в неё входят.
