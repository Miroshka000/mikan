Порт 443 выглядит у сервера самым обычным, и его реже всего блокируют. Но по умолчанию на нём может жить один протокол. Общий порт 443 это **SNI-роутер** ноды: нода сама слушает 443 и раздаёт соединения нужным протоколам по имени сайта, которое клиент называет в начале TLS-рукопожатия (SNI). Так REALITY, VLESS и Trojan с TLS и AnyTLS живут на 443 одновременно, и клиентам не нужен nginx или HAProxy, как в [Подключении за прокси](/mikan/protocols/behind-proxy/).

## Включить

<Steps>

1. Освободите порт 443/tcp на сервере ноды. Если на нём стоит протокол ноды или другая программа, роутер не запустится, а карточка ноды покажет «Порт 443 не занять» и причину. Протокол с 443 (на новой ноде это VLESS · REALITY · XHTTP) перенесите на другой порт, а на третьем шаге включите ему «Через общий 443»: клиенты всё равно придут на 443.

2. **Ноды → нода → Настроить**, переключатель **Общий порт 443 (SNI-роутер)**. Сохраните.

3. В настройках каждого протокола, который должен жить на 443, включите **Через общий 443**. Если роутер у ноды выключен, панель так и напишет: протокол остаётся на своём порту, пока роутер не включён.

</Steps>

Клиенты получат порт 443 со следующим обновлением подписки.

На общий 443 встают только VLESS, Trojan и AnyTLS по TCP с TLS или REALITY: роутеру нужно прочитать TLS-рукопожатие. Hysteria2, TUIC и другие протоколы на UDP остаются на своих портах.

## Как нода выбирает протокол

Роутер читает первое сообщение клиента и берёт из него имя сайта:

- для **REALITY** это имена сайта маскировки протокола (его SNI);
- для протоколов **на сертификате ноды** (VLESS, Trojan, AnyTLS с TLS) это имя, которое получают клиенты: SNI протокола или, если его нет, домен ноды;
- **незнакомое имя** (и не-TLS трафик) уходит в первый по порядку протокол REALITY и дальше на его сайт маскировки, как у настоящего сервера. Сканер, который пришёл с чужим именем, видит обычный сайт.
- **протокол за CDN** (в его настройках задан адрес CDN, блок «За CDN») с версии 0.5.2.1 забирает незнакомые имена и подключения без имени вместо REALITY: CDN приходит на сервер под именем из своих настроек (хост источника, сам домен зоны, без имени для источника по адресу), и панель его знать не может. Посторонний со своим именем получает то, что этот протокол отвечает не своему клиенту: сертификат ноды и заглушку.

Поэтому у каждого протокола на общем 443 должно быть своё имя. Два протокола REALITY с одним и тем же сайтом маскировки роутер различить не сможет: для одного из них возьмите другой сайт.

## Настоящий IP клиента

Протоколы за роутером слушают только на loopback (127.0.0.1) на своих портах. Роутер передаёт им соединение вместе с PROXY protocol: заголовок несёт адрес клиента. Поэтому **устройства, лимиты и фильтры по-прежнему видят настоящий IP**, а не 127.0.0.1. Свой порт протокола не исчезает из списка, но снаружи он закрыт: наружу смотрит только 443. В подписке панель сама подставляет клиентам порт 443.

PROXY protocol поддерживает ядро Citrus, на котором в бете работают ноды, см. [Ноды](/mikan/nodes/nodes/).

## Что проверить, если не работает

- Карточка ноды показывает ошибку роутера, если 443 занят.
- Порт 443/tcp открыт в файрволе сервера и у хостера.
- У протокола с TLS на сертификате ноды есть домен ноды с публичным сертификатом.
- Клиент обновил подписку и получил порт 443.

## Пресет «Безопасный»

С версии 0.5.2.1 всё описанное на этой странице включается одним действием: **Настройки** → **Безопасность** → **Пресеты безопасности** → «Безопасный» → **Показать изменения**. Панель перечисляет по нодам, что изменит: какие протоколы уйдут за общий 443, какие получат новый сайт маскировки (сначала домен панели и домен подписок, затем сайты рядом с сервером), где включится SNI-роутер, блокировка API ноды и заглушка. Ничего не записывается, пока вы не нажмёте **Применить**.

Чего пресет сделать не может, он называет отдельно: протоколу не хватило сайта, порт 443 занят протоколом, который не может его делить, в «Открытых портах сервера» стоит SSH. Клиенты подключаются по старым адресам, пока не обновят подписку. «Стандартный» возвращает протоколы на собственные порты тем же способом.
