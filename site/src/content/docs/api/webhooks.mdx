Панель отправляет свои события на ваш адрес: оплатили тариф, подписка скоро кончится, нода перестала отвечать. Опрашивать API не нужно: на каждое событие панель делает один запрос POST с телом JSON, а подпись в заголовке доказывает, что запрос её, а не чужой.

<Steps>

1. **Подготовьте обработчик** на своём сервере: он принимает POST с JSON и отвечает кодом 2xx. Адрес должен быть доступен панели по `http` или `https`.

2. **Добавьте адрес в панели**: **Настройки → Безопасность → Webhooks → Открыть → Добавить адрес**. Укажите название, адрес и события: все или только отмеченные.

3. **Скопируйте секрет**. Он выглядит как `whsec_...` и показывается один раз: панель хранит его только чтобы подписывать запросы, потом называет лишь последние четыре символа.

4. **Проверяйте подпись** в обработчике, как показано ниже.

5. **Нажмите «Проверить»** у адреса: панель сразу пошлёт событие `webhook.test` и покажет ответ приёмника. Каждая попытка, тестовая тоже, записывается в журнал **Доставки**.

</Steps>

Адреса webhooks настраиваются только из панели, ключом API их не прочитать и не изменить: адрес решает, куда уходят события, а в самом адресе бывает токен.

## Что приходит

Запрос `POST` с телом JSON и заголовками:

| Заголовок | Значение |
|---|---|
| `Content-Type` | `application/json` |
| `User-Agent` | `mikan-webhooks/<версия панели>` |
| `X-Mikan-Event` | тип события, например `payment.paid` |
| `X-Mikan-Event-Id` | номер события, он же `id` в теле |
| `X-Mikan-Timestamp` | время этой попытки, секунды Unix |
| `X-Mikan-Signature` | подпись: `v1=<hex>` |

Тело одинаково для всех событий, различается только `data`:

```json
{
  "id": 1042,
  "type": "payment.paid",
  "at": "2026-10-25T14:03:11Z",
  "user_id": 87,
  "tg_id": 123456789,
  "data": {
    "payment_id": 7,
    "kind": "new",
    "provider": "stars",
    "amount": 100,
    "currency": "XTR",
    "tariff_id": 2,
    "tariff_name": "Месяц",
    "term_days": 30,
    "created": true
  }
}
```

- `id` растёт с каждым событием панели: по нему события упорядочиваются и отличаются друг от друга.
- `at` время события в UTC, RFC 3339.
- `user_id` номер подписки, `tg_id` аккаунт Telegram, к которому событие относится. Если их нет, полей в теле нет.
- В `data` поля с пустым значением (ноль, `false`, пустая строка) не передаются.

## Проверка подписи

Подпись это HMAC-SHA256 в hex, ключом служит весь секрет вместе с `whsec_`, а подписывается строка из времени в секундах, точки и тела запроса ровно в тех байтах, в каких оно пришло:

```text
hex( HMAC-SHA256( секрет, X-Mikan-Timestamp + "." + тело ) )
```

Время входит в подпись, поэтому перехваченный запрос нельзя ни пересобрать с другим телом, ни выдать за новый позже. Каждая попытка подписывается заново: повтор через несколько часов тоже приходит со свежим временем, и окно в пять минут его не отбросит.

Проверяйте по порядку:

1. Возьмите **тело как байты**, до разбора JSON: если пересобрать его из объекта, байты изменятся и подпись не сойдётся.
2. Отбросьте запрос, у которого `X-Mikan-Timestamp` отличается от вашего времени больше чем на 5 минут.
3. Посчитайте подпись и сравните с `v1=...` **посимвольно за постоянное время** (`timingSafeEqual`, `compare_digest`), не оператором `==`.
4. Не сошлось: ответьте 401 и ничего не делайте.

Префикс `v1=` называет схему. Если следующая версия панели подпишет и по другой схеме, она встанет рядом с `v1`, поэтому проверяйте именно часть, которая начинается с `v1=`.

<TabItem label="Node.js">

```js
import crypto from "node:crypto";
import express from "express";

const SECRET = process.env.MIKAN_WEBHOOK_SECRET; // whsec_...
const app = express();

// The signature covers the bytes as they came: take the body raw, not parsed.
app.post("/mikan-webhook", express.raw({ type: "application/json" }), (req, res) => {
  const stamp = req.get("X-Mikan-Timestamp") ?? "";
  const given = /(?:^|[ ,])v1=([0-9a-f]+)/.exec(req.get("X-Mikan-Signature") ?? "")?.[1] ?? "";
  const expected = crypto.createHmac("sha256", SECRET).update(`${stamp}.`).update(req.body).digest("hex");

  const a = Buffer.from(given);
  const b = Buffer.from(expected);
  const same = a.length === b.length && crypto.timingSafeEqual(a, b);
  const fresh = Math.abs(Date.now() / 1000 - Number(stamp)) <= 300;
  if (!same || !fresh) return res.sendStatus(401);

  const event = JSON.parse(req.body.toString("utf8"));
  console.log(event.id, event.type, event.data);
  res.sendStatus(204); // 2xx: taken, the panel sends the next one
});

app.listen(3000);
```

<TabItem label="Python">

```python
import hashlib
import hmac
import os
import re
import time

from flask import Flask, abort, request

SECRET = os.environ["MIKAN_WEBHOOK_SECRET"].encode()  # whsec_...
app = Flask(__name__)


@app.post("/mikan-webhook")
def mikan_webhook():
    # The signature covers the bytes as they came: take the body raw, not parsed.
    body = request.get_data()
    stamp = request.headers.get("X-Mikan-Timestamp", "")
    match = re.search(r"(?:^|[ ,])v1=([0-9a-f]+)", request.headers.get("X-Mikan-Signature", ""))
    given = match.group(1) if match else ""
    expected = hmac.new(SECRET, stamp.encode() + b"." + body, hashlib.sha256).hexdigest()

    same = hmac.compare_digest(given.encode(), expected.encode())
    fresh = stamp.isdigit() and abs(time.time() - int(stamp)) <= 300
    if not same or not fresh:
        abort(401)

    event = request.get_json()
    print(event["id"], event["type"], event["data"])
    return "", 204  # 2xx: taken, the panel sends the next one
```

printf '%s.%s' "$TIMESTAMP" "$BODY" | openssl dgst -sha256 -hmac "$SECRET"

## Доставка

- **Один запрос на одно событие**, события идут по порядку `id`. Пока адрес не принял событие, те, что за ним, ждут.
- **Принято**: ответ 2xx. Всё остальное значит «не принято»: 4xx и 5xx, обрыв соединения, ответ дольше 10 секунд и перенаправление 3xx (панель по нему не идёт). Тело ответа панель не сохраняет, важен только код.
- **Не принятое событие отправляется снова.** Пауза между попытками удваивается от 1 секунды до 5 минут и после успеха начинается заново. Если вы поправили адрес, секрет или переключатель локальных адресов, панель пробует сразу, не дожидаясь паузы.
- **События хранятся 7 дней.** Приёмник, который лежал сутки, получит всё пропущенное по порядку, когда поднимется. Выключенный адрес не получает ничего, события ждут его те же 7 дней. Событие, которое адрес не принял за это время, в журнале помечается «Не отправлено».
- **Доставка «хотя бы один раз».** Если ответ потерялся по дороге, то же событие придёт снова. Храните `id` принятых событий и пропускайте уже виденные.
- **Отвечайте быстро.** Панель ждёт ответ 10 секунд, а следующее событие не уйдёт, пока не закончилось это. Разбор и тяжёлую работу делайте после ответа.
- **Новый адрес получает события с момента создания**, прошлые не присылаются. С выбранным типом события так же: добавленный в выбор тип действует с этого момента, а недельная история этого типа не высылается.

Журнал **Доставки** у адреса показывает, что и когда отправлено, с каким кодом ответил приёмник и почему не принял (адрес закрыт, имя не находится, отказ в соединении, нет ответа в срок, ошибка TLS, перенаправление, ошибочный код). Записи хранятся 7 дней после последней попытки.

## Секрет

У каждого адреса свой секрет. Кнопка **Изменить → Новый секрет** выпускает другой: старый перестаёт подписывать сразу. События, которые приёмник отклонял, пока вы подставляли новый секрет, панель отправит снова, ничего не потеряется. Порядок такой: нажмите кнопку, сразу скопируйте секрет и поставьте его у приёмника.

## Какие адреса можно

- Только `http` и `https` с именем хоста. Логин, пароль и `#фрагмент` в адресе не принимаются: приёмник узнаёт панель по подписи, а не по паролю.
- Публичный адрес можно сразу. Адрес этого сервера или его локальной сети (`localhost`, имя без точки, `10.x`, `172.16.x`, `192.168.x`, `100.64.x`) работает только с переключателем **Разрешить локальные адреса**.
- Облачные адреса метаданных (`169.254.x.x` и другие известные) закрыты всегда, переключатель их не открывает.
- Имя проверяется при каждой отправке по тому адресу, к которому панель подключается, поэтому имя не получится направить на закрытый адрес уже после сохранения.
- Адресов не больше 20.

## События

Выбор событий в панели берёт этот же список. Тип, которого нет в таблице, добавит следующая версия панели: приёмник, который выбрал «Все события», получит его без изменений, поэтому незнакомый тип лучше пропускать, ответив 2xx.

| Событие | Когда | Поля `data` |
|---|---|---|
| `payment.paid` | платёж применён: подписка создана или продлена, пакет зачислен | `payment_id`, `kind` (`new`, `renew`, `package`, `trial`, `device`), `provider`, `amount` в минимальных единицах валюты, `currency`, `tariff_id`, `tariff_name`, `package_id`, `term_days`, `created` |
| `payment.refunded` | платёж возвращён и выданное им забрано; `user_id` равен 0, если подписки уже нет или возврат сделан вручную | те же, вместо `created` есть `disabled` (подписка выключена) |
| `user.created` | подписку создал админ, купили, взяли как пробную или бесплатную; импорт не считается | `source` (`admin`, `bot`, `trial`, `free`), `tariff_id` |
| `user.granted` | аддон с правом `users:grant` добавил дни или трафик | `days`, `bytes`, `pool_id`, `addon` |
| `user.expiring` | подписка кончится через 3 или 1 день, какие дни, решают переключатели админа | `days`, `expires_at` |
| `user.expired` | подписка закончилась | `expires_at` |
| `user.started` | подписка, срок которой ждал первого подключения, пошла: от этого подключения или по решению админа | `expires_at`, `by` (`connection`, `admin`) |
| `user.switched` | следующий тариф, назначенный подписке, включился, когда кончился срок: срок от этого конца и новый период трафика | `tariff_id`, `from_tariff_id`, `expires_at`, `carried` |
| `user.removed` | панель удалила подписку по правилам админа: срок кончился столько дней назад, а подключений с тех пор не было; такого `user_id` в API уже нет | `by` (`inactive`), `expired_at`, `online_at`, `days` |
| `traffic.90` | израсходовано 90% трафика | `period_from` |
| `traffic.100` | трафик израсходован полностью | `period_from` |
| `trial.started` | аккаунт взял пробный период | `tariff_id`, `paid`, `payment_id` |
| `trial.not_given` | аккаунт заплатил за пробный период, который ему уже нельзя дать, подписка не создана | `payment_id`, `provider`, `amount`, `currency`, `tariff_id`, `term_days`, `reason`, `refund` (`auto`: деньги вернулись, следом придёт `payment.refunded`; `manual`: вернуть вручную должен админ) |
| `device.bound` | устройство заняло место в подписке | `device_id`, `label`, `shared` |
| `device.unbound` | устройство потеряло место | те же и `by` (`subscriber`, `admin`, `ban`, `idle`, `reissue`, `limit`) |
| `node.down` | нода не ответила на три проверки подряд, это около 15 секунд | `node_id`, `name`, `code`, `since` |
| `node.up` | нода, которая была недоступна, снова отвечает | `node_id`, `name`, `down_since` |
| `balance.topup` | админ одобрил или отклонил пополнение баланса | `topup_id`, `status` (`approved`, `rejected`), `amount`, `currency`, `balance`, `reason` |

Время в полях `data` (`expires_at`, `since`, `down_since`, `period_from`) это секунды Unix. Событие `webhook.test` с кнопки проверки в этот список не входит, его нельзя выбрать: оно уходит только на тот адрес, у которого нажата кнопка.
