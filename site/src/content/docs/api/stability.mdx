Здесь записано, на что можно опираться скриптам и интеграциям, и чего нельзя ждать. Всё это относится к методам [справочника](/mikan/api/reference/), которые вызываются ключом API.

## Версия

- **В адресе**: `/api/v1`. Все методы лежат под ним.
- **В файле OpenAPI**: у файла, скачанного из панели (**Настройки → Безопасность → API → Скачать OpenAPI**), `info.version` равна версии этой панели. Справочник на сайте подписан номером самого нового релиза из [списка изменений](/mikan/changelog/).
- **У SDK**: версия [SDK](/mikan/api/sdk/) совпадает с версией панели, для которой он собран.

## Что меняется без предупреждения

В любом релизе могут появиться новые методы, новые необязательные параметры запросов, новые поля в ответах и новые значения у перечислений (например, у `state`). Читайте ответы так, чтобы лишнее поле и неизвестное значение ничего не ломали. Python-клиент из [SDK](/mikan/api/sdk/) строже: он отказывается от значения перечисления, которого не знает, поэтому его ставят той же версии, что и панель.

## Где записаны изменения

Всё, что ломает вызывающий код (метод или поле удалены или переименованы, значение больше не принимается), записывается в [списке изменений](/mikan/changelog/) в разделе релиза, отдельным пунктом **«Изменения API»**, с указанием, что заменяет прежнее. Такой пункт есть, например, в `0.5.2.0`: там `POST /api/v1/tariffs/{id}/apply-pools` заменён на `POST /api/v1/tariffs/{id}/apply`. Тот же текст виден в заметках релиза на GitHub и на экране обновлений в панели.

Точную разницу между двумя релизами даёт файл спецификации. Каждый pull request проверяется: файл `web/src/api/openapi.json` должен совпадать с тем, что отдаёт код, иначе проверка не проходит. Поэтому разницу видно так:

```bash
git diff <старый тег> <новый тег> -- web/src/api/openapi.json
```

Проверка появилась недавно, у более ранних тегов файл мог отставать от кода.

## Срок до удаления

Метод или поле, которые собираются убрать, сначала объявляются устаревшими и после этого остаются рабочими **не меньше 30 дней и не меньше одного стабильного релиза**. Объявление состоит из двух частей:

- пункт «Изменения API» в списке изменений с тем, чем заменить;
- метка `deprecated: true` в файле OpenAPI: в справочнике она показывается у метода или поля.

Удаление записывается в «Изменения API» ещё раз.

Правило действует с появления этой страницы. Раньше метод удалялся сразу, как `apply-pools` в `0.5.2.0`, с заменой в том же релизе.

## На что это не распространяется

- **Методы «только сессия»** (вход, сессии, ключи, операции с деньгами и адресами клиентов: в справочнике они так и помечены). Ключ API их не вызовет, они обслуживают экраны самой панели и меняются вместе с ними. Изменения в них тоже попадают в «Изменения API», но срок до удаления на них не распространяется.
- **API аддонов** (`/panel/v2` и прокси Bot API для [своего бота](/mikan/api/own-bot/)): у него свои версии, это протокол аддонов, описанный в [PROTOCOL-v2.md](https://github.com/getmikan/marketplace/blob/main/PROTOCOL-v2.md).
