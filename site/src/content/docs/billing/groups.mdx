Группа решает, что видят её клиенты и как выглядит их подписка. У неё могут быть свои серверы вместо серверов тарифа, адреса для клиентов можно выдавать по группам, а оформление подписки можно задать группе своё. Например, группа «Мобильные РФ» видит только два протокола и подключается через CDN, а «VIP» видит все серверы тарифа, получает свой шаблон Clash и свою страницу подписки.

Группы не путаются с папками: папка только наводит порядок в списке и ни на что не влияет, а группа меняет подписку и то, куда ноды пускают клиента.

## В какой группе клиент

Клиент состоит не более чем в одной группе:

1. **Своя группа** задаётся в карточке клиента: блок «Группа» → «Сменить».
2. Без своей группы клиент в **группе тарифа**. Её задают в форме тарифа, в блоке «Что входит» → **«Группа клиентов»**. Так покупатели и пробные этого тарифа попадают в группу сами, без ручных переносов.
3. Без того и другого клиент ни в какой группе и видит серверы своего тарифа.

Пункт «Как в тарифе» в меню карточки снимает свою группу: клиент возвращается в группу тарифа. Своя группа сильнее группы тарифа, и карточка об этом напоминает.

Сменить группу сразу многим можно массовым действием: отметьте клиентов в списке, **«В группу»**, выберите группу. Панель сначала покажет, скольких это изменит. Пункт «Как в тарифе» снимает своих группы со всех отмеченных.

## Группы и доступ

**Клиенты → Группы** открывает список групп. Кнопка с карандашом открывает группу, у неё две вкладки: **«Доступ»** и **«Оформление»**. На вкладке «Доступ» у группы название, значок и цвет, как у папки, и **серверы**:

- **Как в тарифе клиента**: группа не меняет серверы, клиент видит серверы своего тарифа.
- **Свои**: отмеченные ноды целиком (с протоколами, которые появятся на них потом) и отдельные протоколы. Они **заменяют** серверы тарифа у всех клиентов группы.

Порядок такой: свой список протоколов в карточке клиента, затем свои серверы группы, затем серверы тарифа, а без тарифа все серверы. Карточка в «Ещё настройки» → «Протоколы» пишет, откуда взялись серверы клиента.

Серверы группы действуют сразу и не только в подписке: ноды пускают клиента только на них. Группы серверов с их лимитами работают как раньше: закрытая для клиента группа серверов остаётся закрытой и у группы клиентов со своими серверами. Пакеты трафика и подарки к оплате тарифа проверяются по серверам, на которых стоят клиенты тарифа: если у группы тарифа свои серверы, то по ним.

Проверить, что получит конкретный клиент, можно в его карточке, в блоке **«Что получит клиент»**: там видны его группа, шаблон, заголовки, серверы в подписке и всё, что в неё не попало, с причиной. Подробнее: [что получит клиент](/mikan/subscriptions/clients/#что-получит-клиент).

## Адреса по группам

У каждого адреса для клиентов (**Протоколы** → «Настроить» → «Адреса для клиентов») есть поле **«Группы»**: всем, только выбранным группам или всем, кроме выбранных. Подробнее об адресах: [несколько адресов для клиентов](/mikan/protocols/behind-proxy/).

На вкладке «Доступ» видно, какие адреса выдаются по группе и как: «только группам» или «всем, кроме группы».

## Оформление

На вкладке **«Оформление»** задаётся, как выглядит подписка клиентов группы. Всё, что задано здесь, получают только клиенты группы, поверх **Настройки → Подписка**. Пустое поле и «Как для всех» берут настройку для всех и меняются вместе с ней.

- **Шаблоны**: свой шаблон каждого ядра, Clash, sing-box и Xray. Для клиентов группы он вместо шаблона по умолчанию, а правило ответа, которое называет свой шаблон, сильнее группы. Подробнее: [какой шаблон получит приложение](/mikan/subscriptions/templates/#какой-шаблон-получит-приложение).
- **Что показывают приложения**: название подписки с переменными, объявление и его ссылка, ссылка на поддержку и как часто приложения обновляют подписку, в часах (без своего значения раз в час). Переключатель «Без объявления» убирает объявление у группы, даже если оно задано для всех.
- **Свои заголовки**: заголовки, которые несёт каждый ответ подписки клиентам группы, например для своих настроек приложения. Проверяются так же, как дополнительные заголовки правил ответа: до 10, без заголовков кэша и длины. Заголовки правила ответа сильнее.
- **Устройства**: требовать ли ID устройства и свои правила отвязки: сколько устройств подписчик отвязывает сам и через сколько отвязанное возвращается. Сама привязка устройств общая для всех: если она выключена, эти правила не действуют.
- **Адреса**: где клиенты группы подключаются к протоколу вместо его адреса по умолчанию. Можно задать свой адрес, порт, SNI, Host, имя в подписке и отметку «Впереди CDN». Пустое поле оставляет как есть. Адрес проверяется так же, как адрес для клиентов у протокола. Дополнительные адреса протокола не меняются: кому они выдаются, задаётся у них самих.
- **Страница подписки**: своя страница группы вместо страницы для всех. «Сделать свою» копирует страницу для всех, «Открыть редактор» открывает **Настройки → Страница подписки** для этой группы, «Вернуть страницу для всех» удаляет свою. Бренд, его цвет, картинки и инструкции у всех страниц общие. В Mini App остаётся страница для всех: там клиент становится известен только после входа.

Оформление, адреса и страницу группы меняют только из сессии администратора, как и настройки подписки, которые они заменяют. Ключ API их только читает.

## Удаление

Удаление группы не удаляет ни клиентов, ни тарифы: клиенты возвращаются к серверам и оформлению своих тарифов или к настройкам для всех, тарифы остаются без группы. Оформление, адреса и страница группы удаляются вместе с ней. Адрес, который выдавался «всем, кроме» только этой группы, снова выдаётся всем. Адрес «только выбранным», у которого не осталось групп, не выдаётся никому, пока ему не выберут другие. Окно удаления предупреждает, сколько таких адресов.

## API

- `GET`, `POST /api/v1/groups`; `PATCH`, `DELETE /api/v1/groups/{id}`; `PUT /api/v1/groups/order`. Серверы группы задаются полем `servers`: `{"as_tariff": false, "nodes": [...], "inbounds": [...]}`.
- Оформление группы в поле `appearance`: `templates` (`mihomo`, `singbox`, `xray`), `title`, `announce` (пустая строка: без объявления), `announce_url`, `support_url`, `update_hours`, `headers`, `require_hwid`, `unbind`, `addresses` (`inbound_id`, `address`, `port`, `sni`, `host`, `name`, `cdn`). `null` или не переданное поле: как для всех. `PATCH /api/v1/groups/{id}` с `appearance` заменяет оформление целиком, только из сессии администратора.
- Своя страница группы: `GET`, `PUT`, `DELETE /api/v1/groups/{id}/page`. Тело `PUT` такое же, как у `PUT /api/v1/sub-page` без бренда и его цвета; `DELETE` возвращает группе страницу для всех.
- У клиента `group_id` (своя группа) и `effective_group_id` (группа сейчас: своя или тарифа). `PATCH /api/v1/users/{id}` с `group_id` задаёт свою группу, `0` снимает её.
- У тарифа `group_id`: группа его клиентов без своей. В `PUT /api/v1/tariffs/{id}` `0` снимает её, не переданное поле оставляет как есть.
- Список клиентов фильтруется параметром `group` (`all`, `none` или id группы) и считает клиентов по группам в `group_counts`. Массовое действие `group` с `group_id` даёт клиентам свою группу, без `group_id` снимает её.
- У адреса для клиентов поля `group_mode` (`only`, `never` или пусто) и `groups` (id групп).
