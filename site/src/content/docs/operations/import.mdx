**Настройки → Импорт** переносит пользователей из Marzban, PasarGuard, Remnawave или 3x-ui. Доступ к базе старой панели не нужен: всё идёт через её API, а сама старая панель не меняется. Порядок переезда целиком, от установки до выключения старой панели: [Переезд на mikan](/mikan/start/migrate/).

## Перенести

<Steps>

1. Выберите панель и укажите **Адрес старой панели**, например `https://panel.example.com`, без пути админки. У 3x-ui адрес нужен вместе с портом и секретным путём панели, как вы открываете её в браузере: `https://panel.example.com:2053/path`.

2. Доступ:
   - **Marzban**: логин и пароль администратора;
   - **PasarGuard**: логин и пароль или API-ключ с правом `users:read`;
   - **Remnawave**: API-токен с правом чтения пользователей;
   - **3x-ui**: логин и пароль администратора или API-токен (Настройки → API-токены, в новых версиях). Если администратор входит с кодом двухфакторной защиты, нужен токен. В 3x-ui 3.11 логин и пароль при установке случайные (их пишет журнал 3x-ui при первом запуске), `admin`/`admin` не подходит. Самоподписанный сертификат 3x-ui импорт не принимает: если у панели нет настоящего сертификата, укажите адрес `http://` — так можно только к этому серверу или в локальной сети.

3. Выберите **Тариф**: пользователи получат его протоколы, правило сброса трафика и группы серверов.

4. «Проверить» покажет, сколько пользователей найдено, сколько новых и сколько уже есть.

5. «Перенести» запускает импорт в фоне, страницу можно закрыть.

</Steps>

Переносятся лимит трафика, израсходованный трафик, срок, лимит устройств и заметка. Пользователи с именами, которые уже есть в mikan, пропускаются. Не переносятся старое правило сброса, группы и подключения. Пользователи «на паузе» начинают срок с момента импорта.

### 3x-ui

В 3x-ui клиенты живут внутри инбаундов, поэтому импорт собирает их в пользователей так:

- клиенты с одним `subId` на любых инбаундах — это один пользователь, одна подписка. Его имя — `email` первого из них (по порядку инбаундов), заметка — их комментарии, контакт — Telegram ID;
- лимиты в 3x-ui у каждого клиента свои, у пользователя они складываются: лимит трафика — сумма лимитов, израсходованный трафик — сумма; если у одного из клиентов лимита нет, нет его и у пользователя. Срок — самый поздний, бессрочный клиент делает бессрочным пользователя;
- лимит устройств — `limitHwid` из 3x-ui 3.x, а в версиях, где его нет, — лимит одновременных IP (`limitIp`), самый большой из клиентов;
- срок «с первого использования» (отрицательный `expiryTime`) начинается с момента импорта, как у «на паузе» в других панелях;
- клиент без `subId` переносится отдельным пользователем без старой ссылки;
- клиент, который есть только на инбаундах протоколов, которых нет в mikan (VMess, WireGuard, MTProto и другие), не переносится: «Проверить» показывает его среди тех, кого mikan не возьмёт, с причиной. Если у того же `subId` есть клиенты на протоколах mikan, пользователь переносится по ним, а лимиты, срок и трафик такого клиента в него не входят. Протоколы mikan: VLESS, Trojan, Shadowsocks, Hysteria2 и TUIC.

Пользователь выключен, только если выключены все клиенты его `subId`. Клиента, которого 3x-ui выключил сам, когда кончились срок или трафик, mikan переносит истёкшим или исчерпавшим лимит, а не выключенным: после продления он снова работает. Лимиты и сроки самих инбаундов не переносятся.

:::caution
Ссылки, отозванные в старой панели, после импорта снова работают. Если это важно, перевыпустите их.
:::

## Старые ссылки подписок

Чтобы клиенты ничего не меняли, направьте старый домен на сервер mikan и настройте карточку **Старые ссылки подписки**:

- **Путь старых ссылок**: `sub` для Marzban и PasarGuard, `api/sub` для Remnawave. У 3x-ui это «Путь подписки» из его «Настройки → Подписка» (по умолчанию `sub`): старая ссылка — `subId` клиента, он переносится как есть. Пусто: выключено.
- Для Marzban и PasarGuard нужен ещё **Секрет подписи старой панели**. Он лежит в базе старой панели:

  ```sql
  SELECT secret_key FROM jwt;
  ```

  Без него старые ссылки не откроются.
- Порт подписки задайте в **Настройки → Подписка**, если старая панель отдавала подписки на другом порту.

Бот принимает старые ссылки, а карточка пользователя показывает старую ссылку (Remnawave, 3x-ui) или что она работает. Перевыпуск ссылки отключает и старую.

## Бот продаж Bedolaga

Если вы продавали подписки Remnawave через бота [Bedolaga](https://github.com/BEDOLAGA-DEV/remnawave-bedolaga-telegram-bot), после пользователей можно перенести и его аккаунты: кто чей владелец, балансы и историю транзакций.

<Steps>

1. Сначала перенесите пользователей из Remnawave этого бота, как описано выше.

2. Включите в боте Web API: `WEB_API_ENABLED=true` и ключ в `WEB_API_DEFAULT_TOKEN` в его `.env`, затем перезапустите бота. По умолчанию API слушает `127.0.0.1:8080` на сервере бота. Если mikan стоит на другом сервере, откройте порт только для него или поставьте перед API прокси с HTTPS.

3. В **Настройки → Импорт** выберите **Bedolaga**, укажите адрес API (`http://127.0.0.1:8080`, если бот на этом же сервере) и ключ.

4. «Проверить» покажет, у скольких аккаунтов нашлись подписки, сколько денег на балансах перенесётся и сколько транзакций.

5. «Перенести аккаунты» запускает перенос в фоне.

</Steps>

Что переносится:

- **Владелец подписки.** Аккаунт находит свою подписку по ссылке: в ней короткий UUID Remnawave, который импорт сохранил как старую ссылку. Если ссылки нет, аккаунт ищется по контакту `tg:<id>`, который пишет импорт из Remnawave. Подписка, у которой в mikan уже есть владелец, остаётся с ним. После переноса клиенту не нужно заново привязывать подписку в боте mikan.
- **Баланс.** Рубли из бота ложатся на внутренний баланс mikan, один раз: повторный перенос не добавит их снова. Если баланс в mikan ведётся не в рублях (**Платежи → Способы оплаты**), сумма пересчитывается по его курсу. Клиент видит перенос в истории баланса с пометкой «Bedolaga».
- **История транзакций.** Завершённые пополнения, оплаты и возвраты хранятся отдельно от платежей mikan: они не попадают в выручку, и их нельзя вернуть из панели. Их отдаёт `GET /api/v1/balances/{tg_id}` в поле `imported`.

Промокоды «только для новых» эти аккаунты уже не получат: mikan считает их клиентами с той даты, когда их увидел бот. Рефералы, промогруппы и автоплатёж не переносятся.
