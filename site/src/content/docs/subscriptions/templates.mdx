:::note[С версии 0.5.2.1]
Шаблоны подписки появились в 0.5.2.1. Раньше у панели был один свой профиль Clash, теперь он стал шаблоном Clash по умолчанию.
:::

Шаблон подписки задаёт конфиг ядра целиком: DNS, TUN, группы, правила. Серверов в нём нет, серверы пользователя панель подставляет сама при каждом запросе подписки. Шаблоны лежат в **Настройки → Подписка → Шаблоны**, у каждого ядра свой список, до 20 шаблонов по 512 КБ. Размер считается в байтах: буква кириллицы занимает два байта, так что текст с русскими комментариями упрётся в лимит раньше.

## Ядра и приложения

| Ядро | Текст | Кто получает |
| --- | --- | --- |
| Clash (mihomo) | YAML | Koala Clash, FlClash, Clash Verge, Mikan, Kabosu и другие приложения на mihomo. Stash всегда получает встроенный профиль. |
| sing-box | JSON | Официальные приложения sing-box (SFA, SFI, SFM) и ссылки с `?format=singbox`. |
| Xray | JSON | Happ и INCY, когда включены «Конфиги Xray для Happ и INCY» (**Настройки → Подписка**), и ссылки с `?format=xray`. |

Приложения, которые получают только ссылки (v2RayTun, v2rayNG, Hiddify, Karing и другие), шаблонов не получают.

## Какой шаблон получит приложение

1. Правило ответа выбрало шаблон (**Настройки → Подписка → Правила ответа**, ответ «Выдать профиль», поле «Шаблон»), и это шаблон ядра приложения: профиль собирается из него.
2. Иначе из шаблона ядра по умолчанию. Он у ядра один, а выбирают его кнопкой «Сделать по умолчанию» в списке или переключателем в редакторе.
3. У sing-box и Xray нет своего шаблона по умолчанию: группы и правила они берут из шаблона Clash, выбранного так же, правилом или по умолчанию.
4. Нет и его: приложение получает профиль, который панель собирает из настроек маршрутизации.

Кнопка **Проверить** на странице правил ответа показывает, из какого шаблона соберётся профиль для этого User-Agent. Шаблон, который выбирает правило, удалить нельзя: сначала уберите его из правила.

Если шаблон не соберётся для какого-то пользователя, его приложение получит встроенный профиль, а в лог панели уйдёт предупреждение.

## Редактор

Рядом с текстом виден профиль, который получит пользователь со всеми подключениями. Он обновляется, пока вы пишете, ключи в нём условные. При сохранении панель проверяет шаблон на таком же пользователе, а ошибка называет строку, группу или тег.

- **Взять из настроек маршрутизации** (Clash): текущий встроенный профиль как отправная точка, группы в нём просят серверы сами.
- **Вставить пример** (sing-box и Xray): рабочий конфиг с TUN или локальными прокси, DNS через туннель и локальными сетями напрямую.
- **Загрузить готовый**: шаблон из каталога панели, у каждого указаны автор, лицензия и источник. Текст попадает в редактор, а сохраняется, только когда вы сохраните шаблон; сама панель готовые шаблоны в список не добавляет.
- Готовые куски для Clash добавляют DNS fake-ip, TUN, sniffer, блокировку QUIC, группу по стране или по ноде.

### Готовые шаблоны

| Шаблон | Ядро | Что делает |
| --- | --- | --- |
| mikan | Clash | Встроенный профиль с текущими настройками **Маршрутизации**, то же, что «Взять из настроек маршрутизации». |
| mikan | sing-box, Xray | Тот же пример, что «Вставить пример». |
| privWL · только заблокированное | Clash | Автор — Nemu-x, автор списков [privWL-clash](https://github.com/Nemu-x/privWL-clash). Режим «Только заблокированное» и сверх него списки адресов privWL-clash: замедляемые диапазоны Cloudflare, AWS и других и адреса заблокированных сайтов. Они ловят приложения, которые резолвят имена сами (свой DoH) и проходят мимо fake-ip. DNS как во встроенном профиле: DoH через VPN, российские имена через Яндекс. |

Кнопка «Загрузить готовый» видна, только когда у ядра есть что-то кроме своего шаблона mikan: его и так дают кнопки «Взять из настроек маршрутизации» и «Вставить пример».

Шаблон privWL ссылается на списки по адресу, а не копирует их, и адреса закреплены на коммите, как и у встроенных маршрутов: изменение в репозитории списков не дойдёт до приложений, пока вы сами не поменяете коммит в тексте шаблона. Шаблоны Clash доходят и до sing-box, и до Xray: группы и правила панель переводит так же, как у любого своего шаблона Clash. sing-box получает списки целиком, а конфиги Xray (Happ, INCY) — только то, что есть в geo-файлах приложения, поэтому списки privWL до них не доходят, и в этих приложениях такой шаблон пускает всё напрямую.

Текст шаблона видят только администраторы: ключи API без полного доступа и операторы поддержки получают его скрытым, потому что в шаблоне могут быть свои серверы и секреты.

## Шаблон Clash

Серверы пользователя панель подставит сама, раздел `proxies` не пишите. Группа получает их так:

```yaml
proxy-groups:
  - name: VPN
    type: select
    include-all-proxies: true        # все серверы пользователя
    exclude-filter: "Hysteria"       # фильтры как в mihomo
  - name: Германия
    type: url-test
    mikan:
      nodes: [Germany]               # ноды по имени или id
      types: [vless, hysteria2]      # типы протоколов
rules:
  - MATCH,VPN
```

- Группа, в которую для этого приложения не попал ни один сервер, получает REJECT.
- После вашего `MATCH,<группа>` панель добавит `MATCH,REJECT`, а перед вашими правилами поставит прямые маршруты к адресам панели и нод.
- Пока у Clash есть шаблон по умолчанию, настройки **Маршрутизации** (режим, сервисы, DNS, свои правила) в Clash-приложения не попадают.

## Шаблон sing-box

Конфиг sing-box без серверов. Панель добавит серверы пользователя в `outbounds` после ваших, с тегами по их именам, и заполнит группы, которые их просят:

```json
{
  "outbounds": [
    {"type": "selector", "tag": "VPN", "outbounds": ["Авто"], "mikan": {}},
    {"type": "urltest", "tag": "Авто", "mikan": {}},
    {"type": "selector", "tag": "Германия", "mikan": {"nodes": ["Germany"], "types": ["vless", "hysteria2"]}},
    {"type": "direct", "tag": "direct"}
  ],
  "route": {
    "rules": [
      {"action": "sniff"},
      {"protocol": "dns", "action": "hijack-dns"},
      {"ip_is_private": true, "outbound": "direct"}
    ],
    "final": "VPN"
  }
}
```

- `"mikan": {}` читается только в `selector` и `urltest`: группа получает все серверы после тех выходов, что перечислены в ней самой. `nodes` (имя ноды или id), `types` (vless, hysteria2, ss…) и `filter` (регулярное выражение по имени сервера) сужают выбор.
- Группа без серверов получает выход `REJECT`: соединения через неё не проходят.
- Свой выход с именем сервера остаётся на месте, сервер с этим именем не добавляется.
- Прямые маршруты к адресам панели и нод встают перед вашими правилами `route`, сразу после `sniff` и `hijack-dns`. Если выхода `direct` нет, панель добавит его сама.
- При сохранении панель проверяет JSON, теги выходов и наборов правил, а также то, на что ссылаются группы, правила, `route.final`, `detour` и DNS.

## Шаблон Xray

Один конфиг Xray без серверов. Из него панель делает список: по конфигу на каждый сервер пользователя, где сервер становится выходом `proxy` и получает всё, что не забрали правила.

```json
{
  "outbounds": [
    {"tag": "direct", "protocol": "freedom"},
    {"tag": "block", "protocol": "blackhole"}
  ],
  "routing": {
    "rules": [
      {"ip": ["geoip:private"], "outboundTag": "direct"},
      {"network": "tcp,udp", "outboundTag": "proxy"}
    ],
    "balancers": [
      {"tag": "Авто", "mikan": {"choice": true}, "strategy": {"type": "leastPing"}},
      {"tag": "Германия", "mikan": {"nodes": ["Germany"]}, "strategy": {"type": "random"}}
    ]
  },
  "observatory": {"subjectSelector": ["proxy"], "probeUrl": "https://www.gstatic.com/generate_204"}
}
```

- Балансировщик с `"mikan": {}` получает все серверы пользователя, `nodes`, `types` и `filter` сужают выбор. Серверы попадают в те конфиги, правила которых ведут в этот балансировщик, с тегами `proxy-1`, `proxy-2`…
- Балансировщик с `"choice": true` получает ещё и свой конфиг в начале списка: в нём он стоит вместо `proxy`. Так в Happ и INCY появляется пункт автовыбора.
- Балансировщик без серверов ведёт в `blackhole`.
- Теги, которые начинаются с `proxy`, ставит панель, свои так не называйте.
- Прямые маршруты к адресам панели и нод встают перед вашими правилами.
- При сохранении панель проверяет JSON, теги выходов и балансировщиков и то, куда ведут правила. Правилу нужен `outboundTag` или `balancerTag`.
