У панели есть REST API для ботов, биллинга и мониторинга. Все методы с параметрами и ответами собраны в [справочнике](/mikan/api/reference/) на этом сайте, а тот же справочник встроен в саму панель. Руководства: [создать пользователя](/mikan/api/create-user/), [свой бот](/mikan/api/own-bot/), [SDK](/mikan/api/sdk/), [webhooks](/mikan/api/webhooks/), [стабильность и изменения](/mikan/api/stability/).

## Где документация

Справочник методов: [все методы API](/mikan/api/reference/). В нём у каждого метода параметры, тело запроса, ответы и примеры, а ещё сказано, какой ключ нужен.

В самой панели: **Настройки → Безопасность → API → Открыть**. На странице:

- адрес API и ключи;
- список всех методов с параметрами, ответами и примерами curl, кнопка «Попробовать» для GET-запросов;
- «Скачать OpenAPI»: файл `mikan-openapi.json`, в котором уже прописан адрес вашей панели. Подходит для Postman, Insomnia, Swagger UI и генераторов клиентов.

:::caution
В скачанном файле есть секретный путь вашей панели. Не публикуйте его.
:::

Адрес API: `https://<адрес панели>:<порт>/<секретный путь>/api/v1`.

## Ключи

На странице API кнопка **Новый ключ**:

- **Название**.
- **Права**: «Чтение» или «Полный доступ».
- **Срок**: пока не отзовёте, 30, 90 или 365 дней.
- Пароль администратора и код 2FA, если она включена.

Ключ показывается один раз, панель хранит только его хеш. Ключи создаются и отзываются только из панели, не через API. При смене пароля ключи администратора можно отозвать галочкой, а `mikan reset-password` отзывает их всегда.

| Права | Что можно |
|---|---|
| Чтение | только GET: пользователи, статистика, настройки, метрики. Ссылок подписок и секретных адресов в ответах нет |
| Полный доступ | создавать и продлевать пользователей, менять тарифы и подключения. Без входа, сессий, ключей, журнала аудита, платежей, бота, сертификатов, обновлений и адресов панели: это только из панели |

Ключ передаётся в заголовке:

```http
Authorization: Bearer mk_...
```

Ошибки приходят в формате RFC 9457 (`application/problem+json`), код ошибки в поле `detail`. Когда отказано в полях запроса (422, `detail` равен `validation`), код у каждого поля свой: `errors[].message`, а поле в `errors[].location`, например `body.port`; в `errors[].value` бывает то, что код называет (занятый порт, номер строки правила).

Отказы, связанные с ключом: 401 `unauthorized` (ключ неверный, отозван или истёк; частые неудачи с одного адреса временно закрывают вход: 429 `rate_limited`, срок в заголовке `Retry-After`), 403 `read_only_key` (ключ «Чтение» пробует менять данные) и 403 `session_only` (метод только для сессии администратора).

## Примеры

```bash
BASE="https://vpn.example.com:PORT/СЕКРЕТНЫЙ-ПУТЬ/api/v1"
KEY="mk_..."
```

Список активных пользователей:

```bash
curl -H "Authorization: Bearer $KEY" "$BASE/users?state=active&limit=10"
```

Создать пользователя на тарифе 2:

```bash
curl -X POST "$BASE/users" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"name": "Anna", "tariff_id": 2, "contact": "@anna"}'
```

В ответе пользователь с `id` и ссылкой на подписку `sub_url`. Подробнее: [Создать пользователя по ключу](/mikan/api/create-user/).

Продлить на 30 дней или на месяц (нужно одно из двух):

```bash
curl -X POST "$BASE/users/42/extend" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"days": 30}'
```

Начислить 10 ГБ, которые действуют до расхода:

```bash
curl -X POST "$BASE/users/42/grants" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"bytes": 10737418240, "lifetime": "used"}'
```

## Все методы

Список методов не ведётся вручную: справочник собирается при каждой сборке сайта из файла `web/src/api/openapi.json`, который сама панель выгружает командой `mikan openapi`. Методы сгруппированы по разделам панели, у каждого есть ключ, который он принимает: любой, только «Полный доступ» или только сессия администратора.

[Открыть справочник](/mikan/api/reference/)

## Баланс клиентов и статистика промокодов

В панели для этих методов нет экранов: они нужны скриптам, например чтобы свести балансы с учётом или собрать отчёт по промокодам. Это [сводка по промокодам](/mikan/api/reference/operations/promocode-stats/), [баланс Telegram-аккаунта с его последними операциями](/mikan/api/reference/operations/get-balance/) и [ручное изменение баланса](/mikan/api/reference/operations/adjust-balance/).

Оба GET открыты любому ключу, и «Чтение», и «Полный доступ»:

```bash
curl -H "Authorization: Bearer $KEY" "$BASE/promocodes/stats"
curl -H "Authorization: Bearer $KEY" "$BASE/balances/123456789"
```

Суммы баланса и его операций приходят в сотых долях валюты (`currency` в ответе): плюс значит «пришло», минус «ушло». `kind` операции: `topup`, `spend`, `refund` или `adjust`.

Изменение баланса двигает деньги клиента, поэтому ключ API его не вызовет: ответ 403 `session_only`. Оно доступно только из сессии администратора, с телом вроде `{"delta": -5000, "note": "возврат за простой"}`. `delta` задаётся в сотых долях валюты, минус списывает, а ниже нуля баланс не уйдёт (ответ `balance_low`). `note` обязателен и виден клиенту в истории баланса. Каждое изменение пишется в журнал аудита.
